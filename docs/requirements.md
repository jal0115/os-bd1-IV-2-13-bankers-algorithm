# Шаардлага ба шалгалтын үр дүн

**IV-2-13 · Banker's Algorithm · Бие даалт 2**

Энэ хүснэгтэд сурах бичгийн үндсэн шаардлага болон II-4-10 багийн
шүүмжийн дагуу хийсэн өөрчлөлтийг нэгтгэв. Автомат тестийн дүн,
хөтчөөр хийсэн гар шалгалт, баримт бичгийн ажлыг тус тусын
нотолгоотой нь тэмдэглэв.

## 1. Алгоритм ба хэрэглэгчийн интерфейс

| Шаардлага | Хэрэгжүүлсэн байдал | Шалгасан арга |
|---|---|---|
| Нөөцийн эхний төлөв үүсгэх | CLI нийт нөөцийг аргументаар, Max ба Allocation-ийг файлаас авна. Нийт нөөцөөс хуваарилсан нэгжүүдийг хасаж Available-ийг олно. | Номын жишээнд нийт `(10,5,7)` өгөхөд Available `(3,3,2)` гарсан. |
| Аюулгүй дараалал олох | Цөм Need-ийг `Max − Allocation` гэж тооцож, Work хүрэлцэх процессуудыг дараалан сонгоно. | `tests/test_core.py`. Номын жишээний дараалал болон Work-ийн таван алхмыг `docs/data-format.md` дахь JSON-той тулгасан. |
| Нөөц хүсэх, чөлөөлөх, төлөв харах | CLI нь `RQ`, `RL`, `*`, `exit` командыг дэмжинэ. Аюултай хүсэлтийн түр олголтыг буцаана. | `tests/test_cli.py`, `tests/test_cli_state_integrity.py`. Дараалсан хүсэлтүүдэд `granted`, `wait`, `unsafe` гарсан. |
| Хүснэгтийн өгөгдөл засах | Max, Allocation, Available-ийг засаж болно. Засварыг батлах хүртэл Request, Release болон Banker горимын сонголт түгжигдэнэ. | Available-ийн R0-ийг 3-аас 4 болгож, «Шалгах» дарсны дараа үйлдлүүд дахин идэвхжихийг хөтчөөр шалгасан. |
| Нөөцийн граф, аюулгүй дарааллыг дүрслэх | `src/ui/graph.js` нь inline SVG ашиглана. Цэнхэр сум Allocation, тасархай сум Need-ийг харуулна. Өмнөх ба дараах алхамд шилжиж Work-ийг ажиглана. | Номын жишээг хөтчөөр тоглуулж шалгасан. Need сумыг процесс дээр хулгана аваачих эсвэл «Need сумыг үргэлж харуулах» сонголтоор харна. |

## 2. Шүүмжийн дараах засвар ба туршилт

| Засвар | Баталгаажуулалт |
|---|---|
| Номын жишээ ачаалахад Banker горим сэргэнэ. | `tests/test_banker_off.py`. Banker-гүй горимоос номын жишээ рүү буцаж P1-д олгоод, P0-ийн аюултай хүсэлтийг буцаахыг шалгасан. |
| CLI командын файлыг `--commands` аргументаар уншина. | `tests/test_cli_commands_file.py`. Файл ба stdin ижил гаралттай, байхгүй файлд код 2 буцна. Debian дээр cp1251 тохиргоотой үед дамжуулсан гаралтыг UTF-8-аар уншиж шалгасан. |
| Вэб ба тест 3×2, 10×5 жишээг ижил файлаас уншина. | `tests/test_ui_scenarios.py`. 3×2 жишээнд P0 нөөц чөлөөлөхөд төлөв SAFE болсон. 10×5 жишээнд аюулгүй дараалал бүх процессыг багтаасан. |
| Вэб хүснэгтийн хэмжээ, POST хүсэлтийн толгойг шалгана. | `tests/test_web_limits.py`, `tests/test_post_headers.py`. 20×8 хэмжээг зөвшөөрч, 21×8 ба 20×9 хэмжээг татгалзсан. Буруу Content-Type-д 415, өөр Origin-д 403 буцсан. |
| Түүх ба тоолуурын утгыг ялгасан. | Хөтчөөр Request, Release хоёул түүхэнд бүртгэгдэж, зөвхөн Request тоолуурт орж байгааг шалгасан. Хуудсыг шинэчлэхэд түүх цэвэрлэгдэж, серверийн хуваарилалт хадгалагдсан. |
| Banker-гүй жишээг «UNSAFE төлөвт хүрэх» гэж нэрлэсэн. | P1-д `(1,0,2)`, дараа нь P0-д `(0,2,0)` олгоход аюулгүй дараалал олдоогүй. Энэ туршилт бодит deadlock үүссэнийг тогтоохгүй. |

## 3. Туршсан орчин ба үлдсэн ажил

- **БД1.** II-4-10 баг Windows 11, Python 3.14.7, Chrome орчинд 64 автомат тест ажиллуулсан.
- **БД2.** IV-2-13 баг Debian 13, Python 3.13.5 орчинд `python -m pytest -q` ажиллуулж, 9 файлын 75 тест тэнцсэн. Вэбийн гар шалгалтыг Firefox дээр хийсэн.
- **Manual.** 2.2 дахь туршсан орчин, 2.5 ба Жишээ 4 дэх CLI команд, Need сумыг харуулах зааврыг БД2 хувилбарт шинэчлэх ажил үлдсэн.
- **Гишүүдийн оролцоо.** БД2 тайланд гурван гишүүний ажлыг commit холбоосоор, бусад гурван гишүүний үүргийг БД1-ийн хавсралтаар баримтжуулсан.
